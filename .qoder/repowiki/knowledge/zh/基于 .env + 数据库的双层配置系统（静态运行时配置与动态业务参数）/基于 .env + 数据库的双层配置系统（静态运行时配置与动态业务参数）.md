## 1. 整体方案

spiderV5 后端采用**两层配置体系**：
- **进程级静态配置**：通过 `python-dotenv` 从 `backend/.env` 加载环境变量，封装为单例 `Settings` 对象，供服务启动、连接池、CORS、爬虫间隔等全局设置使用。
- **运行时持久化配置**：通过数据库表 `system_params` 和 `spider_credentials` 存储可热更新的爬虫调度参数、凭证（Token/Cookie/用户名密码）以及飞书应用密钥，由 `backend/system/credentials.py` 提供统一的 CRUD API（`/api/system/*`），前端可在运行期修改并立即生效。

两套配置互不冲突：`.env` 用于部署环境差异（DB/WMS/DeepSeek/飞书 app_id/app_secret），`system_params`/`spider_credentials` 用于运维人员在线调整业务行为。两者在代码中按优先级叠加使用（例如 `get_feishu_token` 先查 `spider_credentials`，缺失时回退到 `settings.FEISHU_APP_ID/SECRET`）。

## 2. 关键文件与职责

| 文件 | 职责 |
|---|---|
| `backend/config.py` | 定义 `Settings` 类，统一读取 `.env`，提供 `_get_int/_get_bool/_get_list` 类型转换辅助函数；初始化上传目录 |
| `backend/.env` / `backend/.env.example` | 实际环境与模板环境，声明所有可配置项（DB、WMS、FEISHU、PURCHASE、DEEPSEEK、SERVER_*、SPIDER_*、QR_BASE_URL） |
| `backend/database.py` | 基于 `dbutils.PooledDB` 的 MySQL 连接池，连接参数全部来自 `settings.*`，失败时打印明确提示 |
| `backend/main.py` | FastAPI 入口，启动时读取 `settings.SERVER_HOST/PORT/DEBUG/CORS_ORIGINS` 注册 CORS 中间件、启动调度器 |
| `backend/system/credentials.py` | 运行时配置核心：凭证管理（`spider_login`/`manual_sync_credentials`/`feishu_login`）、爬虫调度参数（`CRAWLER_CONFIG_KEYS` 字典驱动的类型校验与默认值）、通用参数存取（`update_param`/`get_params`） |
| `backend/system/router.py` | 暴露 `/api/system/login`、`/api/system/login/feishu`、`/api/system/credentials`、`/api/system/params` 等 REST 接口 |
| `backend/sql/resource_schema.sql` / `resource_init_data.sql` | 定义 `spider_credentials`、`system_params` 等表的 DDL 及初始数据 |
| `windows_setup/*.bat` | Windows 一键部署脚本，调用 `step2_config.bat` 生成/编辑 `.env`，再执行建库、初始化、启动 |

## 3. 架构与设计约定

### 3.1 静态配置（`.env` → `Settings`）
- 加载顺序：`config.py` 检测 `backend/.env` 是否存在，不存在则向 stderr 输出中文警告，仍继续以默认值运行。
- 类型安全：所有数值型配置通过 `_get_int` 解析，非法值自动回退到默认值；布尔型支持 `true/false/1/0/yes/no/on`；列表型用逗号分隔。
- 路径解析：`BASE_DIR = Path(__file__).resolve().parent`，`PROJECT_ROOT = BASE_DIR.parent`，上传目录 `UPLOAD_DIR` 默认指向项目根下的 `uploads/`，并在导入时 `os.makedirs(..., exist_ok=True)`。
- 敏感信息：`DB_PASSWORD`、`FEISHU_APP_SECRET`、`PURCHASE_API_KEY`、`DEEPSEEK_API_KEY` 等仅从 `.env` 读取，不写入数据库。

### 3.2 运行时配置（数据库表 `system_params`）
- 爬虫调度参数集中定义于 `CRAWLER_CONFIG_KEYS` 字典，每个 key 声明 `type`/`default`/`description`，`get_crawler_config` 按此字典批量读取并做类型转换（int/float/string），未设置的 key 返回默认值。
- `crawler_enabled_sources` 在读取时自动拆分为 `enabled_sources_list` 列表，写入时自动将 list join 为逗号分隔字符串。
- `crawler_mode` 规范化为 `auto`/`manual`，`crawler_auto_login` 规范化为 `on`/`off`。
- 通用参数通过 `update_param(param_key, param_value)` 实现 upsert，无 schema 约束，键名由调用方保证。

### 3.3 凭证管理（数据库表 `spider_credentials`）
- 支持三种来源：`wms`（di360 WMS）、`feishu`（飞书共享表）、`purchase`（采购系统）。
- 同一 `source` 只保留一条激活凭证：写入前先将旧记录 `is_active=0`，新记录 `is_active=1`。
- 登录流程：`spider_login` 尝试 POST 到 `https://di360.dfmc.com.cn:24664/api/auth/login`，响应字段兼容 `token`/`authorization`/`access_token`/`tokenHead`，同时提取 Cookie；若网络不可达（公司内网外）则仅保存用户名密码，提示“需公司内网后重试”。
- 飞书 Token：`feishu_login` 调用 `open.feishu.cn` 获取 `tenant_access_token`，并将 `expire_at` 写入 `config_json`；`get_feishu_token` 在未过期时直接复用，过期或强制刷新时重新拉取并写回数据库。
- 列表展示时对长 token 截断至 60 字符，`effective_active` 判断要求 `is_active=1` 且存在真实凭证（token 或 username+password）。

### 3.4 配置读取优先级
以飞书为例（`credentials.get_feishu_token`）：
1. 优先从 `spider_credentials` 表中查询 `source='feishu'` 的活跃凭证（含 `app_id`/`app_secret`）。
2. 若缺失，回退到 `settings.FEISHU_APP_ID` / `settings.FEISHU_APP_SECRET`（即 `.env`）。
3. 仍缺失则记录 warning 并返回空串。
其他模块遵循相同模式：运行时配置 > 静态 `.env` > 硬编码默认值。

## 4. 约定与约束

- **禁止硬编码连接串**：数据库连接、WMS 地址、DeepSeek 基址等必须通过 `settings.*` 注入，`database.py` 连接池构造完全依赖 `config.py`。
- **`.env` 不得提交**：仓库仅包含 `.env.example`，实际 `.env` 由部署脚本（`windows_setup/step2_config.bat`）或手动复制生成。
- **运行时参数必须有 schema**：新增爬虫调度参数必须在 `CRAWLER_CONFIG_KEYS` 中声明 type/default/description，否则 `get_crawler_config` 不会返回该 key。
- **凭证幂等更新**：每次写入前先 `UPDATE ... SET is_active=0 WHERE source=... AND is_active=1`，保证同一来源只有一条有效凭证。
- **调试开关**：`DEBUG=true` 时 uvicorn 启用 `reload=True` 热重载，生产环境应设为 `false`。
- **CORS 白名单**：通过 `CORS_ORIGINS` 逗号分隔传入，默认 `*`，生产环境建议显式指定域名。
- **上传目录自创建**：`config.py` 末尾 `os.makedirs(settings.UPLOAD_DIR, exist_ok=True)`，无需外部准备。

## 5. 适用性说明

本配置系统覆盖后端 FastAPI 服务的启动参数、数据库连接、第三方集成（WMS/飞书/DeepSeek）、爬虫调度策略、凭证生命周期管理等全部配置场景，属于仓库内成熟且被多模块复用的核心基础设施。
