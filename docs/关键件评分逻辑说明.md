# 关键件评分逻辑说明

> 最后更新: 2026-07-13
> 对应代码: `backend/critical_parts/scoring.py`

---

## 一、整体架构

```
用户点击"重新评分"
    │
    ▼
POST /api/critical/{project_id}/score
    │
    ▼
CriticalScorer.score_project_parts(project_id)
    │
    ├── 1. 从 project_parts 表读取所有零件
    ├── 2. 逐个零件四维度评分
    ├── 3. 加权求和 → 分级
    ├── 4. 保存到 critical_scores 表
    └── 5. 返回结果给前端
```

---

## 二、四维评分模型

### 公式

```
关键件总分 = 安全件 × W1 + 大件 × W2 + 紧缺件 × W3 + 工艺件 × W4

默认权重: (W1, W2, W3, W4) = (0.30, 0.20, 0.30, 0.20)
满分: 5.0
```

### 分级阈值

| 总分范围 | 等级 | 颜色 | 含义 |
|----------|:----:|:----:|------|
| ≥ 4.0 | red | 🔴 红色 | 关键件（高风险） |
| 3.0 ~ 3.9 | yellow | 🟡 黄色 | 次关键件 |
| < 3.0 | green | 🟢 绿色 | 常规件 |

## 三、各维度评分规则

### 3.1 安全件（权重 30%）

**方法**: 关键词匹配零件名称

| 关键词 | 说明 |
|--------|------|
| 安全 | 安全相关零件 |
| 制动 | 制动系统 |
| 气囊 | 安全气囊 |
| ABS | 防抱死制动 |
| ESP | 车身稳定系统 |
| 安全带 | 安全带总成 |

**评分**: 命中任一关键词 → **5分**，否则 → **1分**

> 设计意图: 安全件是最高风险维度，命中即满分，确保安全件必然进入关键件候选。

---

### 3.2 大件（权重 20%）

**方法**: 关键词匹配零件名称

| 关键词 | 说明 |
|--------|------|
| 车身 | 白车身/车身结构件 |
| 底盘 | 底盘系统 |
| 发动机 | 发动机总成及部件 |
| 变速 | 变速箱/变速器 |
| 车架 | 车架/大梁结构 |
| 大梁 | 大梁结构 |
| 车桥 | 车桥总成 |

**评分**: 命中任一关键词 → **5分**，否则 → **1分**

> 设计意图: 大型结构件物流/仓储成本高，缺料影响大，命中即满分。

---

### 3.3 紧缺件（权重 30%）

**方法**: 计算到货率，根据到货率分档

```
到货率 = received_quantity / demand_quantity × 100%
```

| 到货率范围 | 评分 | 含义 |
|------------|:----:|------|
| < 30% | 5 | 极度紧缺 |
| 30% ~ 49% | 4 | 严重紧缺 |
| 50% ~ 69% | 3 | 中度紧缺 |
| 70% ~ 89% | 2 | 轻度紧缺 |
| ≥ 90% | 1 | 供应充足 |
| 无数据 | 3 | 默认中性 |

**⚠️ 当前问题**: 
- 阈值可能需要根据实际业务调整（如 30%/50%/70%/90% 是否合理）
- 默认中性值 3 可能导致无到货数据的零件被误判为"中度紧缺"

---

### 3.4 工艺件（权重 20%）

**方法**: 关键词匹配零件名称

| 关键词 | 说明 |
|--------|------|
| 焊接 | 焊接工艺件 |
| 涂装 | 涂装工艺件 |
| 总装 | 总装工艺件 |
| 冲压 | 冲压工艺件 |
| 焊装 | 焊装工艺件 |

**评分**: 命中任一关键词 → **5分**，否则 → **1分**

> 设计意图: 特殊工艺件制造周期长，替代困难，命中即满分。

---

## 四、理论最大分验证

各维度均按 1-5 分制：

```
最大总分 = 5×0.30 + 5×0.20 + 5×0.30 + 5×0.20
         = 1.5 + 1.0 + 1.5 + 1.0
         = 5.0  ✅
```

| 场景 | 安全 | 大件 | 紧缺 | 工艺 | 总分 | 等级 |
|------|:----:|:----:|:----:|:----:|:----:|:----:|
| 全命中 | 5 | 5 | 5 | 5 | **5.0** | 🔴 关键件 |
| 安全+紧缺 | 5 | 1 | 5 | 1 | **3.2** | 🟡 次关键 |
| 仅紧缺 | 1 | 1 | 5 | 1 | **2.2** | 🟢 常规 |
| 无命中 | 1 | 1 | 1 | 1 | **1.0** | 🟢 常规 |

## 五、整体问题总结

### 5.1 评分粒度

| 维度 | 当前档位 | 说明 |
|------|:--------:|------|
| 安全件 | 1 / 5 | 命中关键词→5分，否则→1分 |
| 大件 | 1 / 5 | 命中关键词→5分，否则→1分 |
| 紧缺件 | 1~5 | 按到货率分5档 |
| 工艺件 | 1 / 5 | 命中关键词→5分，否则→1分 |

> 安全/大件/工艺三个维度采用"命中/未命中"二元判定（1或5），简化了评分逻辑。如需更精细的区分，可改为多档评分（如 1/2/3/4/5）。

### 5.2 规则引擎 vs LLM

当前使用**纯规则引擎**（关键词匹配 + 到货率计算），优点是完全透明可解释，缺点是：
- 关键词列表容易遗漏
- 无法理解零件名称的语义（如"转向节"不含"安全/制动"关键词，但实际是安全件）
- 无法利用上下文信息

**建议**: 保留规则引擎作为基础评分，叠加 LLM 作为辅助评估（已有 `LLMEvaluator` 类，但未集成到主流程）。

### 5.3 权重调优

权重存储在 `system_params` 表中，可通过 API 或 SQL 动态调整：

```sql
-- 查看当前权重
SELECT * FROM system_params WHERE param_key LIKE 'critical_weight_%';

-- 调整权重（示例：提高安全件权重到 35%）
UPDATE system_params SET param_value = '0.35' WHERE param_key = 'critical_weight_safety';
```

## 七、修改指南

### 如果要修改关键词列表

编辑 `backend/critical_parts/scoring.py`:

```python
# 第 93-95 行附近
safety_keywords = ["安全", "制动", "气囊", "ABS", "ESP", "安全带"]
size_keywords = ["车身", "底盘", "发动机", "变速", "车架", "大梁", "车桥"]
process_keywords = ["焊接", "涂装", "总装", "冲压", "焊装"]
```

### 如果要修改评分档位

编辑 `backend/critical_parts/scoring.py` 的 `score_project_parts` 方法中对应维度:

```python
# 安全件评分
safety = 5 if any(kw.lower() in name for kw in safety_keywords) else 1

# 大件评分
size = 5 if any(kw.lower() in name for kw in size_keywords) else 1

# 工艺件评分
process = 5 if any(kw.lower() in name for kw in process_keywords) else 1
```

> 如需多档评分，改为阶梯判断，例如:
> ```python
> if "制动" in name: safety = 5
> elif "转向" in name: safety = 4
> elif "悬架" in name: safety = 3
> else: safety = 1
> ```

### 如果要修改到货率阈值

编辑 `backend/critical_parts/scoring.py` 第 107-118 行附近:

### 如果要修改权重
